# Social media kit — usage

Everything in this folder is generated by `scripts/build-social.ts` from `brand/design-tokens.json`, `brand/logos/`, `collateral.config.json` and `content/*.json`. Nothing here is drawn by hand; to change a post, change the content file and rebuild. Regenerate with `pnpm build:social` (or everything with `pnpm build:collateral`).

## Which template for what

| Family | Folder | Feeds from | Use it for |
|---|---|---|---|
| Term of the week | `posts/term/` | `content/glossary.json` (snapshot of the site's authored glossary drafts; 24 terms today, 221 when the site finishes authoring) | One plain-language definition a week. The post and the website say the same thing because they read the same file. |
| State fact | `posts/state-fact/` | `content/state-facts.json` | One statutory fact with its mandatory source line (statute, site, date verified). Never edit the figure on the post; edit the content file and its `sourceNote`. |
| The finding | `posts/finding/` | `content/findings.json` | Quote-cards in the brand voice. No client names, no testimonials until written consent is on file. |
| Seasonal | `posts/seasonal/` | `content/seasonal.json` | Monsoon, wildfire, freeze and open-enrollment reminders. Regional and factual; never alarmist, never a forecast. |
| Referral | `posts/referral/` | `content/referral.json` | **Withheld.** Renders only when `collateral.config.json → referralProgramEnabled` is `true`, which counsel has not done; see `posts/referral/README.md`. |

Sizes rendered for every family: `1080x1080` (feed square), `1080x1350` (feed portrait, the better feed size on Instagram and LinkedIn), `1080x1920` (story). Each size has a standard sample and a Medicare sample; the full glossary set is pre-rendered at 1080×1080 only, and the state facts at 1080×1080.

## The Medicare rule

Any post whose text mentions Medicare (or Medigap, Medicare Advantage, Part D, Medicare supplement) carries the TPMO disclaimer in a fixed footer band, verbatim from `collateral.config.json → medicare.tpmo.text`, at 24 px on a 1080-wide canvas. The generator refuses to export a post that mentions Medicare without the band; there is no flag to turn that off. The two `{{TODO:compliance.tpmo.orgCount}}` / `planCount` tokens render visibly until the client supplies the plan-year counts (site TODO-CLIENT-DATA #11). A post with visible TODO tokens must not be published; that is the point of them.

For families with no Medicare content of their own (term, state fact) the Medicare sample uses the open-enrollment reminder from `content/seasonal.json`, so the band's layout is proven for every family and size.

## Regenerating a single post from a JSON snippet

```
node scripts/build-social.ts post --family term --size 1080x1350 \
  --json '{"id":"binder","term":"Binder","definition":"A temporary written confirmation that coverage is in force while the full policy is issued.","medicare":false}' \
  --out social/posts/term/1080x1350/binder.svg
```

Fields by family: `term` takes `term` + `definition`; `state-fact` takes `headline`, `fact`, `source`; `finding` takes `text`; `seasonal` takes `headline`, `text`, `window`. Add `"medicare": true` to force the band. The command writes the SVG master and the PNG beside it, and runs the banned-phrase and Medicare guards; a refusal prints the reason and writes nothing.

## Banned phrases

Every text layer is checked against `content/banned-phrases.json` (the site's list plus this stage's superlatives). A glossary term whose site definition trips the list is skipped and listed in `posts/SKIPPED.md`; fix the wording at the source. `pnpm check:banned-phrases` re-scans everything that is on disk.

## Safe-zone rules

`banners/safe-zone/` holds an overlay version of every banner: ochre regions with a red outline are cropped or covered somewhere (mobile crop, profile-picture overlap); the dashed green rectangle is the zone the positioning line, the states and the domain must stay inside. The layout keeps everything in that zone, so the client can compare the plain banner and the overlay and see what survives on a phone. When a platform changes its crop, edit the `zones` and `safe` values in `scripts/build-social.ts` (one place) and rebuild.

Banner content is fixed by the brief: the positioning line, the four states, the domain. Nothing else, no photography, no handles until the client supplies them (`collateral.config.json → social.handlesNote`).

## The avatar test

`tests/avatar-row.png` shows the 400 px profile picture at 40 px and 32 px beside neutral stand-in circles, on the light surface and on `surface-inverse`. The mark reads as a stepped block at 40 px and as two blocks with a seam at 32 px; the reversed variant (mark in `brand-ink` on `brand`) holds better on a dark feed and beside saturated avatars, so it is the one to use on X and on any platform with a dark default theme.

A private version of the same row was rendered next to three real national carrier avatars (UnitedHealthcare, Aetna, Humana) and looked at; it is not committed because carrier marks stay out of this repository. Finding: the Desert Peak mark is the only warm-coloured avatar in the row and the only one that is neither a letterform nor a wordmark, so it neither disappears nor resembles a neighbour; at 32 px on a light feed the plain variant is quieter than the carriers' saturated blues and purples, which is acceptable, and the reversed variant matches their weight if that is wanted.

## Hard rules baked into the generator

No rates, no savings claims, no superlatives (banned-phrase guard), no carrier logos, no emoji, no stock imagery, no icons (the token lock fails on any path outside a logo group), no client names, no handles. Colours come from `sem()` only; the mark and lockup are byte-identical copies of `brand/logos/`; type is Archivo and Source Serif 4 from `brand/fonts/`.
