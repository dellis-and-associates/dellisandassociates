# Decks — usage

Two PowerPoint files from one token-driven system, generated by `scripts/build-decks.ts`. Nothing on a slide is typed by hand: colours come from `brand/design-tokens.json`, marks from `web/logos/*.png` (hashed copies of `brand/logos/`), people from `people.json`, state figures from `content/state-facts.json`, disclosures from `collateral.config.json`. Regenerate with `pnpm build:decks`.

| File | For | Medicare |
|---|---|---|
| `client-pitch.pptx` | A coverage review with a client: the comparison, the state minimums, the finding, next steps. | Mentions Medicare on the coverage-summary slide, so the disclosure slide carries the TPMO text. |
| `partner-meeting.pptx` | Internal and partner meetings: how a referral is handled, what a review looks like. | No Medicare content; the disclosure slide omits TPMO. Add Medicare anywhere and the build adds the text or refuses the file. |

## Changing a client name, a date, the agenda

Edit `decks/inputs/client-pitch.json` (or `partner-meeting.json`) and run `pnpm build:decks`. Fields: `deckTitle`, `subtitle`, `clientName`, `date`, `presenter` (a slug from `people.json`), `agenda` (up to six lines), `sectionLine`, `includeMedicareNote`. Values that still read `{{TODO:…}}` render exactly like that on the slide; they are a signal that the input is not finished, not a placeholder to talk over.

Do not edit the .pptx and keep it: the next build overwrites it. If a one-off edit is unavoidable, save it under another name outside `decks/`.

## The ten masters

1 Title · 2 Agenda · 3 Section divider · 4 The comparison · 5 State requirements · 6 The finding · 7 Coverage summary · 8 Next steps · 9 Disclosure · 10 Contact. Each is a named layout in the file and each slide carries a speaker note (≈40 words) saying when to use it. The comparison slide is the reason the deck exists: replace the whole table from the quote sheet, never a single cell; carriers stay "Carrier A/B/C" until appointments are confirmed in writing.

The disclosure slide is generated and is never deleted. It carries the independent-agency line, the licensed states and licence numbers (TODO tokens until supplied), and the TPMO text when Medicare appears anywhere in the deck. `pnpm check:medicare` re-verifies every committed deck.

## Fonts

The decks reference "Archivo" and "Source Serif 4" by name. Install the files in `decks/fonts/` on every machine that opens or presents them (double-click each `.ttf`, or drop them in `~/Library/Fonts` / `C:\Windows\Fonts`). Without them PowerPoint and Keynote substitute Arial and Georgia (the declared fallbacks), which keeps the text legible and, as verified in the renders, does not overflow any box; it just is not the typesetting. Fonts are not embedded in the file: see `DECISIONS-NOTES.md`.

The Archivo files in `decks/fonts/` have tabular figures as their default digits (PowerPoint cannot switch number spacing), so the comparison table aligns without any setting. `decks/fonts/README.md` explains what was changed and the licence.

## Keynote compatibility

- Open the .pptx directly; Keynote converts it. Install the fonts first or Keynote will substitute silently.
- Use no transitions and no builds; the decks ship with none and none should be added. A projected deck in an unknown room should be exported to PDF from the machine that has the fonts.
- Tables convert cleanly; the highlighted column and the totals rule survive. Re-check slide 4 after conversion.
- Keynote may re-flow the 10 pt slide numbers; they are decorative.

## Renders

`renders/{deck}/slide-NN.png` are produced by LibreOffice with the brand fonts and are the reference for what the slides should look like. A fallback-font render (system fonts only) is produced into `.cache/decks/fallback/` on every build for the reflow check; it is not committed.

## Charts

Two chart types only, bar and line, in the token colours; see `CHART-STYLE.md`. No chart is embedded in the templates because no real data exists yet; add charts as native PowerPoint charts, styled per the guide, never as pasted images.
